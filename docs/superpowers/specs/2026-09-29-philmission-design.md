# PhilMission 구현 설계

작성일: 2026-09-29  
상태: 사용자 검토용. 앱 구현 및 개발 도구 설치 전.  
기준: PhilMission_PRD_v2.md와 2026-09-29 사용자의 변경 요청. 충돌 시 아래 변경사항을 우선한다.

## 1. 목표와 결정

한국인 선교 대원이 설치 직후 인터넷 없이 자료를 읽고 현지인에게 보여주는 Android 앱을 만든다. 서버, 로그인, 원격 다운로드를 두지 않는다. UI는 한국어이며 콘텐츠는 따갈로그어·영어 및 한국어 뜻을 제공한다.

사용자가 최소 Android 버전 선정과 필요한 개발 도구 설치를 위임했다. 최소 지원은 Android 8.0(API 26)으로 정한다. 이는 이 프로젝트의 호환성·구현 복잡도 절충안이며 팀 기기 지원율을 확인했다는 의미는 아니다.

| 항목 | 변경한 구현 기준 |
|---|---|
| 가정심방 말씀 | HWPX 원문을 구조화한 텍스트로 표시. PDF로 변환하지 않음 |
| 예배 순서 | 제공 JPG를 앱 안에서 확대·이동하며 열람 |
| 선교 일정 | PDF 열람 기능 유지. 9쪽 원본은 보존 |
| 찬양 | 제공 2곡 + 조사한 전통 찬송 3곡, 총 5곡 목표 |
| 회화·예배문·전도 | 공개 자료를 참고해 초안을 직접 구성하고 출처·검수 상태 기록 |
| 최소 OS | Android 8.0, minSdk 26 |
| 설치 | 필요한 JDK·Android SDK·Gradle을 작업용 도구 경로에 설치하고 재현 절차 기록 |

## 2. 접근 방식

선정안은 Kotlin + Jetpack Compose 네이티브 앱이다. Android 전용 요구, 로컬 PDF 렌더링, 전화 앱 연계, Room/DataStore 저장을 직접 지원하기에 PRD와 가장 잘 맞는다.

Flutter는 향후 iOS 확장에 유리하지만 이번 범위에는 이점이 작고 추가 도구가 필요하다. WebView 기반 앱은 화면 제작이 빠르지만 PDF·수명주기·접근성·로컬 저장 연계를 따로 처리해야 한다. 이번에는 네이티브 구현을 채택한다.

## 3. 화면과 동작

### 공통

하단 탭은 예배 / 회화 / 전도 / 더보기 네 개다. 짙은 녹색 강조색, 밝은 바탕, 충분한 줄 간격을 사용한다. 모든 콘텐츠 화면은 세로 스크롤을 지원한다. 읽기 글자 크기 조절은 3단계로 제공하고 OS 글자 크기 설정도 반영한다. 한국어 독음과 뜻은 원문과 시각적으로 구분한다.

언어 선택은 앱 전체에서 유지한다. 언어 변경 시 문장 ID 또는 카드 인덱스를 유지한다. 뒤로 가기와 회전 후에도 선택한 자료·페이지·검색어를 복원한다. 화면 켜짐 설정은 실제 읽기 화면에만 적용하고 목록·백그라운드에서는 해제한다.

### 예배

예배문 4종, 찬양 5곡, 가정심방 말씀으로 진입한다. 말씀은 제목, 3개 소제목, 문단 단위로 구성한다. HWPX의 따갈로그어·한국어 뜻·독음을 유지하며 영어는 별도 번역 초안으로 추가한다. 원문의 서로 다른 언어 문단이 자동으로 정확히 대응한다고 가정하지 않고 문단별 대조한다. 문장 순서와 원문을 추적할 수 있는 고정 ID를 부여한다.

제공 M4A는 설교 전체 녹음이므로 문장별 녹음으로 잘못 연결하지 않는다. 첫 구현에는 자동 분할·동기화를 넣지 않고, 원본 참고자료로 보존한다. 문장 음성은 대응 구간과 이용 조건을 확인한 파일이 있을 때만 연결한다.

찬양은 원어 가창 가사와 뜻을 구분한다. 제공 2곡은 JPG에서 가사·독음·뜻·코드를 텍스트로 전사하고 시각 대조한다. 코드는 공백으로 정렬하지 않고 짧은 가사 구절별 구조로 보관한다. MR와 악보 뷰어는 만들지 않는다.

### 회화

인사 10, 어린이 사역 15, 배식 10, 심방·위로 10, 응급 의사소통 5로 총 50문장이다. 한국어·따갈로그어·영어 부분 검색, 카테고리, 즐겨찾기를 제공한다. 상세에서 한 번 눌러 큰 글씨로 전환한다. 큰 글씨는 현지 언어만 표시하고 가로·세로 및 긴 문장 스크롤을 지원한다.

응급 문장은 도움 요청, 아픈 위치 질문, 병원 이동 의사 확인 등 의사소통으로 제한한다. 진단·복약·치료 지시는 넣지 않는다.

### 전도

성경을 근거로 직접 작성한 짧은 안내 카드 5장과 영접 기도문을 제공한다. 대화 의사 확인 → 하나님의 사랑 → 죄와 단절 → 예수님의 십자가와 부활 → 믿음의 응답 순서다. 카드 번호, 이전·다음, 안내자용 한국어 설명 접기를 제공한다. 사영리의 원고·삽화·브랜드를 그대로 복제하지 않는다.

### 더보기

- 현장 자료: 선교 일정 PDF, 가정심방 말씀 텍스트 바로가기, 예배 순서 JPG.
- 연락처: 출처·확인일을 포함한 기본 연락처와 개인 연락처 CRUD. 전화는 ACTION_DIAL로 열고 실패하면 번호 복사. 원본 주소는 별도 위치 메모로 제공하고 존재하지 않는 전화번호를 만들지 않음.
- 준비 점검: 콘텐츠 버전, 파일 해시 검사, 검수 상태, 비행기 모드 점검 안내.
- 설정: 언어·읽기 글자 크기·화면 켜짐 유지.

PDF는 Android PdfRenderer로 한 페이지씩 렌더링하며 현재/전체 페이지, 이전·다음, 확대·축소·이동을 제공한다. 회전 시 페이지를 보존하고 이미지 메모리 사용량을 제한한다. JPG는 비율을 유지하며 확대·이동·원래 크기로 복귀를 제공한다. 실패 시 해당 자료의 오류만 표시하고 다른 기능은 계속 쓸 수 있다.

## 4. 자료 조사 및 선정

### 사용자 제공 자료

일정 PDF에는 이름과 가족별 신앙·건강·가정 사정이 포함되어 있다. 원본을 덮어쓰지 않는다. 배포용 일정 사본에서는 개인 사정 부분을 제거하고 일정·준비물·공용 안내를 남긴다. 일정의 모순되거나 불명확한 시간은 추정으로 고치지 않는다. 이미지 위에 사각형만 덮는 방식이 아닌 실제 삭제를 사용하고 텍스트 추출과 렌더링으로 제거 여부를 확인한다.

### 추가 찬양 3곡

선정 후보는 Amazing Grace / What a Friend We Have in Jesus / Jesus Loves Me이다. 현대 필리핀 작곡가의 인기 순위가 아니라 필리핀 교회·교육에서도 사용되는 전통 찬송을 고른다. 영어 원문은 오래된 공개 저작물 판본만 사용한다. 최신 편곡·추가 절·현대 번역을 함께 복제하지 않는다. 따갈로그어·한국어는 새로 작성한 뜻으로 표시하며, 검증되지 않은 번역을 가창용 가사라고 표시하지 않는다.

- Amazing Grace: John Newton의 전통 가사. 필리핀 Taytay, Rizal 교회의 사용 사례: https://www.umc.org/content/philippines-church-name-inspired-by-amazing-grace . 원문·판본 정보: https://hymnary.org/text/amazing_grace_how_sweet_the_sound . 현대 추가 후렴 제외.
- What a Friend We Have in Jesus: Joseph M. Scriven 원문. 공개 이용 안내가 있는 전통 악보: https://hymnary.org/media/fetch/139078 . 필리핀계 교회 사용 사례: https://www.firstfilam.org/history . 현지 협력 교회의 선호까지 확인된 것은 아님.
- Jesus Loves Me: Anna B. Warner의 전통 가사와 William B. Bradbury 후렴. 판본 정보: https://hymnary.org/hymn/LUYH2013/709 . 1971년 추가 절은 제외. 필리핀 방송 사용 사례: https://hopetv.ph/shows/music-and-praise .

### 회화와 예배문

회화는 Peace Corps의 Tagalog Language Packet을 표현·예절 참고자료로 사용하고 사역 상황에 맞는 짧은 문장으로 직접 구성한다. 참고: https://eric.ed.gov/?id=ED402768 . 문장별 원문/번역/독음은 각각 독립 필드로 저장한다.

주기도문·사도신경은 사용자가 제공한 예배순서의 표현을 우선 전사한다. 십계명은 출애굽기 20장에 기초하고 번호 체계는 개신교의 일반적 구분을 따른다. 가정 기도문은 감사·평안·건강·관계·일상의 돌봄을 담은 직접 작성문으로 구성한다. 한국어는 기존 성경 번역을 길게 복제하지 않고 뜻을 직접 작성한다.

성경 인용은 공개 저작물로 명시된 Ang Dating Biblia 1905와 World English Bible의 판본을 구분해 사용한다. 1905/1982라는 명칭만 보고 1982 개정본까지 자유 이용 가능하다고 가정하지 않는다.

- ADB1905: https://www.biblegateway.com/versions/Ang-Dating-Biblia-1905-ADB1905
- WEB: https://ebible.org/details.php?id=engwebp
- 전도 구성 참고: https://www.cru.org/us/en/how-to-know-god/would-you-like-to-know-god-personally.html

위 자료 조사와 작성은 현지 언어·교회 검수의 대체가 아니다. 초안은 검수 대기로 표시한다. 사용자 제공 자료도 제공 사실과 재배포 허가 확인을 별도 기록한다.

## 5. 데이터와 구성 요소

앱 ID 기본안은 org.philmission.app이다. 고정 콘텐츠는 assets JSON/이미지/PDF에 둔다. 사용자 데이터는 Room, 설정은 DataStore에 저장한다. OS 클라우드 백업을 끄고 인터넷·연락처 읽기·위치·마이크·전체 파일 접근 권한을 요청하지 않는다.

주요 구성 요소:

1. ContentRepository: assets 로딩, 안정적인 ID, 누락 파일에 대한 오류.
2. ContentValidator: 문장 수·카테고리 수·필수 언어·중복 ID·참조·검수·이용 조건 검증.
3. UserRepository: 즐겨찾기와 개인 연락처, 삭제 없는 DB 마이그레이션.
4. SettingsRepository: 언어·글자 크기·화면 켜짐 설정 Flow.
5. ReaderScreen: 예배문·말씀 공통 문단 보기.
6. PhraseScreen / SongScreen / GospelScreen: 각 자료의 검색·필터·큰 글씨·카드 상태.
7. DocumentScreen: PDF 페이지 렌더링과 JPG 확대·이동.
8. AudioController: 대응하는 문장 파일이 있는 경우에만 단일 재생. 화면 이탈·언어 변경·백그라운드·오디오 포커스 상실·출력 분리 시 정지.
9. ReadinessScreen: 파일 존재·SHA-256와 콘텐츠 검수 상태를 구분해 표시.

공통 메타데이터는 id, version, source, licenseStatus, reviewStatus, reviewer, reviewedAt을 가진다. 없는 검수자·날짜를 만들어 넣지 않는다. 문장은 tl/en/ko/pronunciationTl/audioTl/audioEn을 가진다. 찬양은 singingLanguage와 meaningTl/meaningEn을 분리한다. 문서 종류는 pdf/image/text로 분리한다.

## 6. 빌드와 배포

안정적으로 호환되는 도구 버전을 공식 문서로 확인하여 고정한다. 검토한 조합은 AGP 8.9.2, Gradle 8.11.1, JDK 17, compile/target SDK 35이며 구현 시 실제 의존성 해결과 빌드로 확인한다. 근거: https://developer.android.com/build/releases/agp-8-9-0-release-notes . Compose·Kotlin·Room·DataStore 버전도 고정하고 동적 버전은 사용하지 않는다.

도구 설치는 프로젝트의 .tools 또는 공용 작업용 경로를 사용하고 소스 관리에서 제외한다. 시스템 전역 설정을 불필요하게 바꾸지 않는다. 다운로드 출처·버전·체크섬·실행 절차를 문서화한다.

검수 대기 자료를 볼 수 있는 개발 APK와 최종 배포 APK를 구분한다. 릴리스 검증은 필요한 콘텐츠의 검수·사용 조건이 미확인일 때 실패하도록 한다. 개발 APK 완성과 현장 배포 가능 상태를 혼동하지 않는다. 서명 키는 소스에 포함하지 않고 같은 앱 ID·키로 버전 코드만 올려 업데이트한다.

## 7. 수용 기준과 검증

- 콘텐츠 검사: 회화 50개 및 10/15/10/10/5 분포, 예배문 4종, 찬양 5곡, 전도 1종, 현장 자료 3종(pdf/image/text), 필수 언어·ID·참조.
- 자동 테스트: 검색·필터·즐겨찾기, 개인 연락처 유효성, 언어 전환 위치 유지, 파일 누락·해시 불일치, 미검수 릴리스 차단.
- Android 테스트: Room 저장 및 업데이트 마이그레이션, DataStore 재실행 유지, 화면 회전·뒤로 가기·큰 글씨 복원.
- 빌드: debug APK 생성, unit tests와 lint 통과. 서명된 릴리스는 검수 조건과 키 준비 후 생성.
- 화면 검증: 한국어/따갈로그어 글꼴, 작은 화면·큰 글자·가로 화면, JPG 확대, PDF 9쪽 원본 및 배포 사본 전 페이지.
- 오프라인 검증: 첫 실행부터 비행기 모드에서 텍스트·PDF·JPG 열기, 전화 앱 실패 시 복사, 선택 음성의 중단 동작.
- 실기기 미확인 항목은 완료로 표시하지 않는다. 기기나 에뮬레이터를 사용할 수 없는 경우 빌드·정적 검사·로컬 테스트의 범위를 결과에 명시한다.

## 8. 다음 작업

이 문서의 검토 후 구현 계획을 파일 단위로 작성한다. 구현 순서는 콘텐츠·로컬 저장 기반 → 공통 화면·예배·회화 → 찬양·전도 → 문서·연락처·설정 → 파일 검사·APK·검증이다. 각 단계의 결과는 다음 단계에서 재사용하며 원본 DATA는 수정하지 않는다.
